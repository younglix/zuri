ISSUE IDENTIFIED:
================================================================================
The mining engine scheduler was NOT running in production (Passenger WSGI) 
because it was only initialized inside the `if __name__ == '__main__':` block.

Location: Bottom of app.py (lines ~1180-1193 before fix)

Problem:
  ❌ When app is imported as a module (passenger_wsgi.py), the scheduler 
     initialization code NEVER executes
  ❌ The `if __name__ == '__main__':` condition is False on import
  ✅ Works locally with `python app.py` (but not in production)

Result: Mining plans never complete their cycle → users never get returns


FIX APPLIED:
================================================================================
Moved scheduler initialization outside the `if __name__ == '__main__':` block

Changes:
  1. Moved database initialization to module level (after error handlers)
  2. Moved scheduler creation and startup to module level
  3. Moved atexit handler to module level
  4. Kept only `app.run()` inside `if __name__ == '__main__':` block

New Structure:
  - init_db() runs when module is imported
  - Scheduler starts when module is imported
  - app.run() only runs in local development

Now the scheduler WILL START in both scenarios:
  ✅ Local: python app.py
  ✅ Production: python -m gunicorn (or Passenger WSGI)
